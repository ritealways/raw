13. VERY IMPORTANT — Do Not Send the Entire CSV to the LLM

Do NOT blindly send the entire dataframe/CSV to the Llama API.

The architecture should be approximately:

User Question
      ↓
Llama
      ↓
Understand user intent
      ↓
Determine required operation
      ↓
Python/Pandas
      ↓
Calculate using actual DataFrame
      ↓
Result
      ↓
Llama
      ↓
Natural-language explanation
      ↓
User

The final numerical answer must come from Python/Pandas calculations, not from LLM guessing.

---

14. Avoid Hallucination

For example, if the user asks:

What is the average revenue?

The application should calculate the actual value from the dataframe.

The LLM can then convert that result into a natural-language response.

The LLM should NOT invent:

- numbers
- counts
- percentages
- dates
- categories
- statistical results

If the question cannot be answered using the uploaded data, respond clearly that the information cannot be determined from the dataset.

---

15. Generalized Question Handling

Do NOT implement this:

if question == "average revenue":
    ...
elif question == "total sales":
    ...

The system must be designed to support generalized questions.

A practical first implementation can use the LLM to identify the required analytical operation and parameters, then execute the operation safely using Python/Pandas.

For example, conceptually:

"What is the average claim amount?"
        ↓
Intent: aggregation
Column: claim_amount
Operation: mean
        ↓
Pandas
        ↓
Actual result
        ↓
LLM explanation

Use a simple and maintainable approach.

Do not introduce a complicated autonomous-agent framework.
