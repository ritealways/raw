2. ⏱️ Time-Series identification question

Don't tell the candidate that it's a time-series problem.

Give them this:

> "You work for an e-commerce company. You have 3 years of transaction data containing customer_id, product_id, region, order_date, quantity, price, discount, and revenue. The business wants to know the expected revenue for each region for the next 3 months so that inventory and staffing can be planned. How would you approach this problem?"



What you are looking for

The candidate should recognize:

This is a time-series forecasting problem.

Expected thinking:

1. Aggregate revenue by region + time period.


2. Define forecasting frequency — daily/weekly/monthly.


3. Sort chronologically.


4. Analyze trend and seasonality.


5. Check missing dates/outliers.


6. Create lag features.


7. Create rolling statistics.


8. Use time-based train/validation split, not random train-test split.


9. Establish a baseline:

Naive

Seasonal naive



10. Try models such as:



XGBoost/LightGBM with lag features

ARIMA/SARIMA where appropriate

Prophet/other forecasting models depending on characteristics.


11. Evaluate using an appropriate forecasting metric such as MAE/RMSE/MAPE, depending on the data.



🔥 Follow-up trap

Ask:

> "Can I randomly split the data into 80% train and 20% test?"



Expected answer:

No.

Random splitting can cause future information to leak into training. The validation must respect chronological order.

3. 🧠 Three intermediate DS questions that are deceptively confusing

Q1. Accuracy vs F1

> "Your fraud model has 98% accuracy. Is that a good model?"



Expected answer:

Not necessarily.

If fraud is only 1% of transactions, predicting every transaction as non-fraud gives approximately 99% accuracy while detecting zero fraud.

Candidate should discuss:

Precision

Recall

F1

PR-AUC

Business cost of false positives vs false negatives

Threshold selection


🔥 Follow-up:

> "If the business says missing one fraud is 10 times more expensive than investigating a false alarm, what would you optimize?"



Good candidate should move toward recall/cost-sensitive optimization, rather than blindly optimizing accuracy.


---

Q2. Data leakage

> "You train a model and get 97% validation accuracy. After deployment, accuracy drops to 72%. What would you investigate first?"



Look for:

Data leakage

Train/validation split problems

Distribution shift

Feature availability at prediction time

Preprocessing performed before splitting

Target leakage

Temporal leakage

Training-serving skew

Concept drift


🔥 Follow-up:

> "Give me an example of target leakage that can look completely legitimate as a feature."



Good example:

For a loan-default model, using "number of collections actions taken after the loan went into default" would be leakage because that information wasn't available when making the original prediction.


---

Q3. Regularization / Bias-Variance

> "Your training accuracy is 99% but validation accuracy is 78%. You increase model complexity and training accuracy becomes 99.9%. What do you expect to happen to validation performance?"



Expected:

Likely overfitting gets worse.

Then ask:

> "Would increasing regularization always improve validation performance?"



Correct answer:

No.

Too much regularization can cause underfitting.

Look for understanding of:

High variance → overfitting → regularization / simpler model / more data

and

High bias → underfitting → more expressive model / better features / less regularization

4. 🐍 Two Python coding problems

I would deliberately avoid extremely difficult LeetCode problems. For this candidate, I would test practical DS coding ability.

Coding Problem 1 — Time-series feature engineering

Give:

import pandas as pd

df = pd.DataFrame({
    "date": pd.to_datetime([
        "2025-01-01", "2025-01-02", "2025-01-03",
        "2025-01-04", "2025-01-05", "2025-01-06"
    ]),
    "sales": [100, 120, 110, 130, 150, 140]
})

Ask:

> "Create two new columns:

1. lag_1 = previous day's sales


2. rolling_3 = average sales of the previous 3 days
Make sure today's sales are not included in the rolling feature."





Expected approach:

df = df.sort_values("date")

df["lag_1"] = df["sales"].shift(1)

df["rolling_3"] = (
    df["sales"]
      .shift(1)
      .rolling(3)
      .mean()
)

🔥 Follow-up

Ask:

> "Why did you use shift(1) before rolling?"



Expected:

To ensure the feature uses only historical information and doesn't include the current target value, preventing data leakage.

This is an excellent test because it connects Python + ML + time series + leakage.


---

Coding Problem 2 — Find duplicate customers with conflicting values

Give:

data = [
    ("C001", "Delhi", 100),
    ("C002", "Mumbai", 200),
    ("C001", "Delhi", 100),
    ("C003", "Pune", 300),
    ("C002", "Mumbai", 250),
    ("C004", "Delhi", 400)
]

Ask:

> "Find customers whose revenue values are inconsistent across records. Return the customer ID and all unique revenue values associated with that customer."



Expected output:

C002 -> [200, 250]

A Pandas solution could be:

df = pd.DataFrame(data, columns=["customer_id", "city", "revenue"])

result = (
    df.groupby("customer_id")["revenue"]
      .unique()
)

result = result[result.apply(len) > 1]

print(result)

🔥 Follow-up

Ask:

> "Now modify it so that you return only the customer IDs."



Then:

> "How would you solve the same problem without Pandas?"



That tests whether they actually understand Python fundamentals rather than just memorizing Pandas syntax.
