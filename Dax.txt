Act as a Senior Data Scientist + Python Developer + Streamlit Developer + LLM/Conversational BI Engineer.

I want to build a Conversational BI Streamlit application from scratch.

I am a beginner in Conversational BI/LLM application development, so keep the implementation simple, practical, and easy to understand.

---

Main Objective

Build a generic Conversational BI application that can work with any CSV file uploaded manually by the user.

The application should:

1. Allow the user to upload any CSV file.
2. Automatically inspect the dataset.
3. Automatically detect column types.
4. Run appropriate EDA based on the detected column types.
5. Display useful tables, statistics, and visualizations.
6. Provide a Conversational BI chat interface where the user can ask questions about the uploaded dataset in natural language.
7. Use a Llama model through an API at the backend to understand user questions and generate answers.
8. The solution should be generic, not hard-coded for only one dataset or insurance dataset.

1. CSV Upload

Create a simple Streamlit interface where the user can:

- Upload a CSV file manually.
- Read the CSV using Pandas.
- Display:

  - Number of rows
  - Number of columns
  - Preview of the data
  - Column names
  - Detected data types

The application should continue working even if the uploaded CSV has completely different columns or belongs to a different business domain.

- Identify strongly correlated numerical columns.

Handle datasets with:

- Missing values
- Constant numerical columns

without crashing.

Automatically detect date/time columns where possible.

For date/time columns:

- Identify maximum date.

This is the most important feature.

Create a Chat / Ask Your Data section.

The user should be able to ask natural-language questions such as:

- "How many rows are there?"
- "What is the average claim amount?"
- "Which region has the highest revenue?"
- "Show me the top 10 products by sales."
- "What is the trend of revenue over time?"
- "Which category has the highest count?"
- "Are there any missing values?"
- "Which numerical columns are strongly correlated?"
- "Compare revenue between regions."
- "What are the main insights from this dataset?"

The application should answer based on the uploaded dataset, rather than giving generic LLM answers.

---

9. Llama API Integration

Use a Llama model through an API as the LLM backend.

Important:

- Do not hard-code the API key.
- Store credentials in ".env" or Streamlit secrets.
- Create a simple configuration mechanism.
- Clearly explain where the user needs to add the API key.
- Keep the LLM integration simple.

The LLM should be used for:

1. Understanding the user's natural-language question.
2. Determining what analysis is required.
3. Generating an appropriate response based on the actual dataset/analysis results.

Do not simply send the entire CSV blindly to the LLM.

Instead, use Python/Pandas to perform calculations and provide the LLM with the relevant structured context/results.

---

10. Prevent Hallucinations

The Conversational BI system should prioritize actual calculated results from Pandas/Python.

For numerical questions:

User:

«What is the average revenue?»

The application should calculate:

df["Revenue"].mean()

and then let the LLM explain the result naturally.

The LLM should not invent numerical values.

If the requested information cannot be determined from the dataset, the application should respond honestly:

«"I cannot answer this question from the uploaded dataset."»
